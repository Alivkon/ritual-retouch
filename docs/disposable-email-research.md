## Проверка ограничения .ru

- `frontend/src/main.ts`, функция `setupAuthForm`, вызывает проверку из
  `frontend/src/utils/registrationEmail.ts`: при вводе полного адреса другой зоны
  показывается сообщение под полем пароля, при отправке проверка повторяется.
  Вход этим правилом не ограничен.
- `frontend/index.html` содержит соответствующее уведомление.
- Изначально на сервере в `src/web/auth.ts`, `POST /api/auth/register`, проверки
  зоны `.ru` не было. Изменением 005 она добавлена: адреса других зон отклоняются
  с HTTP 400 до обращения к БД, с указанным пользователем сообщением.
  Во время ввода полного адреса вне `.ru` форма показывает это же сообщение
  под полем пароля. Вход этим правилом не ограничен.

## Файл доменов и подключение

`src/data/disposable-email-domains.json` — отсортированный JSON-массив
из 175 уникальных доменов только в зоне `.ru`.
В файле перечислены домены email без `@`; это не просто список сайтов сервисов.

Основа — 174 домена зоны `.ru`, отобранных из 9 901 домена публичной базы
[disposable-email-domains/disposable-email-domains](https://github.com/disposable-email-domains/disposable-email-domains),
снимок коммита
[`c619f0a1e359b880ac9d442bb37d22b8391ba12f`](https://github.com/disposable-email-domains/disposable-email-domains/blob/c619f0a1e359b880ac9d442bb37d22b8391ba12f/disposable_email_blocklist.conf).
Лицензия CC0 сохранена в `docs/disposable-email-domains.LICENSE`.
Дополнительно включён `mailgu.ru`, отсутствовавший в этой версии базы:
его почтовый адрес проверен непосредственно в HTML главной страницы сервиса.
Домены других зон, в том числе `maxxspace.com` и `yopmail.com`,
исключены из списка по запросу пользователя.

`src/utils/disposableEmail.ts` загружает список локально, нормализует регистр
и Unicode-домены, проверяет домен и его родительские домены. Например,
`mailgu.ru` блокирует также `sub.mailgu.ru`, но не `notmailgu.ru`
или `mailgu.ru.example.org`.

`POST /api/auth/register` возвращает HTTP 400 с сообщением
«Этот домен относится к сервису временной почты. Для регистрации используйте постоянный почтовый ящик.»
до обращения к БД, хеширования пароля и отправки письма. Некорректные адреса,
в том числе с несколькими `@`, также отклоняются. Вход и восстановление
доступа существующих аккаунтов не менялись.

Форма регистрации проверяет адрес при вводе по тому же JSON-списку доменов,
что и сервер. Предупреждение об одноразовой почте или зоне вне `.ru` появляется
только текстом под полем пароля и скрывается после исправления адреса.
При отправке формы проверка повторяется; адреса с ограничением не отправляются
на сервер. Всплывающие окна ограничений удалены (изменение 007).

## Обновление и проверка

Для добавления домена зоны `.ru` внесите его в JSON-массив в нижнем регистре без `@`,
сохраняя сортировку и уникальность. При обновлении внешней базы сохраняйте
локальное дополнение `mailgu.ru` и фильтр зоны `.ru`, проверяйте изменения и обновляйте сведения
о снимке в этом документе. Домены сервисов меняются, поэтому статический
список требует периодического обновления и не гарантирует полного покрытия.

Проверка:

```bash
yarn build
node --test tests/emailRegistration.test.cjs
```

JSON копируется компилятором TypeScript в `dist/data` и включается в существующий
Docker-образ вместе с `dist`. Для применения изменений в списке нужны пересборка
и перезапуск приложения. Во время регистрации внешние сервисы не вызываются.
