# 011. Автоматическая авторизация в веб-приложении при открытии из Telegram

- **Дата:** 2026-11-08
- **Статус:** выполнено

## Цель

При открытии веб-приложения из Telegram пользователь должен авторизоваться
автоматически — по своему Telegram ID, без ввода email/пароля.

## Анализ

Механизм авторизации по Telegram ID уже существовал, но не срабатывал на
практике:

- Бэкенд: `POST /api/auth/telegram-webapp` (`src/web/auth.ts`) проверяет подпись
  `initData` (HMAC по `BOT_TOKEN`), извлекает Telegram ID и создаёт/находит
  аккаунт через `getOrCreateUser` — тот же аккаунт, что и в боте.
- Фронтенд: при загрузке `frontend/src/main.ts` уже вызывал авто-логин, если
  доступен `Telegram.WebApp.initData`.
- Причина неработоспособности: обычные пользователи попадали на сайт по
  обычной ссылке (например, из сообщений бота). В этом случае страница
  открывается во встроенном браузере **не как Telegram WebApp** — `initData`
  отсутствует, и авто-авторизация невозможна по принципам работы Telegram.
  Точек запуска WebApp для обычных пользователей в боте не было (только
  админ-панель и ЮMoney), скрипт `telegram-web-app.js` не подключался.

## Внесённые изменения

1. `src/index.ts` — при старте бота устанавливается меню-кнопка
   (`setChatMenuButton`, тип `web_app`, текст «Открыть приложение», URL
   `WEBAPP_URL`). Запуск приложения из этой кнопки передаёт `initData` → сайт
   авторизует пользователя по Telegram ID. Установка повторяется при каждом
   старте бота (идемпотентно).
2. `src/keyboards/inline.ts` — в главное меню бота (`mainMenuKb`) добавлена
   inline-кнопка «🌐 Открыть приложение» (`webApp`, `WEBAPP_URL`) — второй
   сценарий запуска WebApp с `initData`.
3. `frontend/index.html` — подключён официальный скрипт
   `https://telegram.org/js/telegram-web-app.js`.
4. `frontend/src/main.ts` — перед чтением `initData` вызываются
   `Telegram.WebApp.ready()` и `expand()` (с безопасной обработкой отсутствия
   API вне Telegram); чтение `initData` защищено проверкой типа.

Сама логика авто-логина (запрос `POST /api/auth/telegram-webapp`, сохранение
сессии в `localStorage`, переход на дашборд) не менялась — она уже была
реализована корректно.

## Выполненные проверки

1. `yarn build` (tsc) и `yarn build:frontend` — успешно.
2. `docker compose build bot && docker compose up -d bot` — деплой прошёл,
   логи чистые, polling активен.
3. `getChatMenuButton` — меню-кнопка бота теперь `web_app` с URL
   `https://ritual-retouch.ru/`.
4. Живой сайт отдаёт новую сборку: в HTML присутствуют
   `telegram-web-app.js` и новый бандл `assets/index-*.js`;
   в бандле есть обращения к `initData`, `ready`, `expand`;
   в `dist/keyboards/inline.js` есть кнопка «Открыть приложение».

## Применение

Изменения применены: образ пересобран, контейнер перезапущен.

## Ограничения

- Автоавторизация работает только при запуске сайта как Telegram WebApp
  (кнопка меню бота или inline-кнопка «🌐 Открыть приложение»). При открытии
  сайта по обычной ссылке в браузере (в т.ч. во встроенном браузере Telegram)
  Telegram не передаёт `initData` — это ограничение платформы, в этом случае
  остаётся обычный вход или привязка аккаунта через `/start link_…`.
