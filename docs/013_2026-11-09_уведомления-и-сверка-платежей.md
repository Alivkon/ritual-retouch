# 013. Уведомления и сверка платежей YooKassa

- **Дата:** 2026-11-09 (Europe/Belgrade)
- **Статус:** выполнено и применено

## Цель

Получать админское сообщение об успешно обработанных оплатах и выявлять платежи YooKassa, которые прошли, но не были записаны/зачислены приложением.

## Изменения

1. Сохранены уведомления администратору Telegram после успешного зачисления; ошибки отправки таких уведомлений теперь также попадают в журнал приложения.
2. Добавлены тревожные сообщения `ADMIN_ID` при ошибке проверки/сопоставления/зачисления платежа. При ошибке зачисления webhook отвечает HTTP 500, чтобы YooKassa могла повторить доставку.
3. Добавлена периодическая сверка: при запуске и затем каждые 15 минут запрашиваются платежи YooKassa за последние 7 дней. Если платёж со статусом `succeeded` отсутствует в БД, администратору отправляется предупреждение с суммой, аккаунтом и ID платежа.
4. Сверка не начисляет генерации автоматически: она только уведомляет, чтобы не дублировать ручное начисление. Для подавления повторных сообщений и учёта разрешённых инцидентов добавлена таблица `yookassa_payment_alerts`; уведомления повторяются при сбое доставки с интервалом не менее 10 минут.
5. Добавлен тест пагинации и фильтрации сверки: в уведомление попадают только успешные платежи, отсутствующие в БД.

- `yarn build` — успешно.
- `node --test tests/*.test.cjs` — 4 теста пройдены, ошибок нет.
- `get_errors` для изменённых TypeScript/тестовых файлов — ошибок не найдено.
- `docker compose build bot && docker compose up -d bot` — успешно; контейнер `ritual_retouch` запущен.
- После запуска таблица `public.yookassa_payment_alerts` присутствует в PostgreSQL. В проверенных startup-логах ошибок сверки не было.

## Применение

Изменения развернуты: Docker-образ бота пересобран, сервис `bot` перезапущен. При старте выполняется первичная сверка, далее — каждые 15 минут.

## Примечание

Подписку YooKassa на webhook `payment.succeeded` нужно настроить в кабинете магазина отдельно. Периодическая сверка является дополнительным механизмом и обнаруживает пропущенные webhook даже без клиентского возврата на сайт.
