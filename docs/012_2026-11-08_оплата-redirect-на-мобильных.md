# 012. Исправление ошибок оплаты на мобильных устройствах (redirect ЮKassa)

- **Дата:** 2026-11-08
- **Статус:** выполнено

## Цель

Устранить «плавающие» ошибки при оплате на сайте через ЮKassa: на компьютере
оплата проходит, на телефонах процесс прерывается на разных этапах, а в личном
кабинете ЮKassa платежи фиксируются как неуспешные.

## Анализ

- Серверные логи не содержат ошибок: все запросы создания платежа
  (`/api/web/payment/yookassa`, `/api/payment/create`) возвращали 200, ошибок
  YooKassa API нет.
- Причина сбоя — встроенный checkout-виджет ЮKassa внутри мобильного WebView
  Telegram: этапы 3-D Secure и переключения в банковские приложения
  (SberPay, СБП) в WebView ненадёжны, что даёт случайные отказы на разных
  этапах. На десктопе виджет работает — поведение соответствует известной
  проблеме интеграции «виджет внутри Telegram Mini App на мобильных».
- Решение: на мобильных устройствах вместо встроенного виджета использовать
  **redirect-подтверждение ЮKassa** — пользователь переходит на полноценную
  страницу оплаты `yookassa.ru`, где мобильные сценарии (3-D Secure, СБП,
  SberPay) работают штатно. После оплаты webhook ЮKassa зачисляет пакет, бот
  отправляет пользователю сообщение об успешной оплате, а при возврате на сайт
  (`return_url` с параметром `payment_success=1`) открывается окно кошелька с
  актуальным балансом.

## Диагностика после первого деплоя (redirect внутри WebView)

Через API ЮKassa (`GET /v3/payments?limit=10`) проверены последние платежи:
все они создавались успешно (500₽), пользователь доходил до страницы ЮKassa и
выбирал способ оплаты (`sberbank`, `tinkoff_bank`), но платежи оставались в
статусе **pending** — не завершались. Это подтвердило: страница ЮKassa,
открытая внутри WebView Telegram, не может переключиться в банковское
приложение (SberPay и аналоги).

## Финальное решение

На мобильных устройствах страница оплаты ЮKassa открывается **во внешнем
браузере** через `Telegram.WebApp.openLink(confirmation_url)` (вне Telegram —
обычная навигация). Внешний браузер корректно обрабатывает 3-D Secure и
переключения в банковские приложения. Живой тест подтвердил: оплата с телефона
проходит успешно.

## Внесённые изменения

1. `src/web/paymentRoute.ts` (`/api/web/payment/yookassa` — оплата на сайте):
   - `yookassaCreatePayment` принимает параметр `flow`; при `redirect`
     создаётся платёж с `confirmation: { type: "redirect", return_url }`;
   - маршрут читает `flow` из запроса и возвращает `confirmation_url`.
2. `src/webServer.ts` (`/api/payment/create` — страница оплаты из бота):
   - те же изменения для `flow: "redirect"` и `confirmation_url`.
3. `frontend/src/api.ts` — `createYookassaPayment(amount, flow)` передаёт
   выбранный сценарий и возвращает `confirmation_url`.
4. `frontend/src/pages/wallet.ts` — на мобильных устройствах (по
   `navigator.userAgent`) вместо виджета выполняется переход на
   `confirmation_url`; на десктопе поведение прежнее (виджет).
5. `static/pay_yookassa.html` (страница «🌐 ЮMoney» из бота) — та же логика:
   на мобильных — redirect, на десктопе — виджет.

## Выполненные проверки

1. `yarn build` (tsc) и `yarn build:frontend` — успешно.
2. Два деплоя (`docker compose build bot && docker compose up -d bot`) — бот
   запущен, polling активен, логи чистые.
3. На живом сайте проверено: `/pay_yookassa` содержит redirect-логику с
   `tg.openLink` (2 вхождения), актуальный SPA-бандл содержит обработку
   `confirmation_url` и `openExternalUrl`, в контейнерных `dist/webServer.js`
   и `dist/web/paymentRoute.js` присутствует `confirmation_url`.
4. Диагностика через API ЮKassa: до исправления платежи на мобильных
   оставались `pending` (выбран `sberbank`/`tinkoff_bank` и не завершались).
5. **Живой тест после исправления: оплата с телефона прошла успешно**
   (подтверждено пользователем).

## Применение

Изменения применены: образ пересобран, контейнер перезапущен.

## Примечания

- Зачисление оплаты не зависит от сценария: работает webhook `/yookassa/webhook`
  и fallback-подтверждение; при redirect-оплате пользователь также получает
  сообщение от бота «✅ Оплата прошла успешно!».
- `return_url` ведёт на главную страницу с `?payment_success=1` — при возврате
  сайт показывает окно кошелька и опрашивает баланс до зачисления (до 30 сек).
