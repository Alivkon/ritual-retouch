# 010. Уведомления администратору об остановке и ошибках бота

- **Дата:** 2026-11-08
- **Статус:** выполнено

## Цель

При остановке бота и возникновении критических ошибок отправлять сообщение
администратору (`ADMIN_ID`) в Telegram, чтобы сбои не оставались незамеченными.

## Внесённые изменения

Все изменения — в `src/index.ts`:

1. Добавлен хелпер `notifyAdmin(text)` — отправка служебного сообщения админу
   через `bot.api.sendMessage` с экранированием HTML (`escapeTelegramHtml`,
   т.к. глобальный трансформер задаёт `parse_mode: HTML`). Если экземпляр бота
   ещё не создан, уведомление молча пропускается. Сбои самой отправки не
   влияют на работу бота (логируются как предупреждение).
2. Функция `runPolling(bot)` — цикл запуска polling'а с уведомлениями:
   - **409 Conflict** (параллельный инстанс с тем же токеном): ретраи каждые
     30 секунд (логика из задачи 009 сохранена), уведомление админу отправляется
     не чаще одного раза в час (`conflictNotifiedAt`), чтобы не заспамить чат;
   - **иные ошибки polling'а**: уведомление
     «🚨 Бот остановил приём сообщений из-за ошибки polling: …» и остановка цикла.
3. Функция `registerLifecycleHandlers(bot)`:
   - `SIGTERM` / `SIGINT` — уведомление «🛑 Бот останавливается (сигнал …)»,
     затем `bot.stop()` и корректный выход;
   - `uncaughtException` — уведомление «🚨 Критическая ошибка (uncaughtException): …»
     и завершение процесса с кодом 1;
   - `unhandledRejection` — уведомление «🚨 Необработанное отклонение промиса …»
     (процесс продолжает работу).
4. В `main().catch()` при фатальной ошибке запуска отправляется уведомление
   «🚨 Критическая ошибка запуска бота: …» (если бот уже создан).

2. `docker compose build bot && docker compose up -d bot` — образ пересобран,
   контейнер пересоздан; в `dist/index.js` внутри контейнера присутствует
   `notifyAdmin` (7 вхождений), логи чистые, соединения к Telegram API активны.
3. **Живой тест остановки**: `docker restart ritual_retouch` — админ получил
   в Telegram сообщение «🛑 Бот останавливается (сигнал SIGTERM)» (подтверждено
   пользователем). После рестарта polling восстановлен (2 активных соединения
   к `api.telegram.org:443`), ошибок в логах нет.

## Применение

Изменения применены: образ пересобран и контейнер перезапущен. Бот работает,
уведомления об остановке и ошибках доставляются админу.

## Ограничения и примечания

- Если фатальная ошибка происходит до создания экземпляра бота (например,
  отсутствуют переменные окружения), уведомление отправить невозможно — остаётся
  только лог в stdout/`docker logs`.
- Уведомление «🛑 Бот останавливается» приходит при каждом рестарте контейнера,
  включая плановые перезапуски при деплое — это ожидаемое поведение.
