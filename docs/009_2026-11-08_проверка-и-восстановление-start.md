# 009. Проверка прохождения команды /start и восстановление polling

- **Дата:** 2026-11-08
- **Статус:** выполнено

## Цель

Проверить, что команда `/start` корректно доходит до обработчика и обрабатывается
ботом, и устранить обнаруженные проблемы.

## Обнаруженные проблемы

1. **Polling был остановлен безвозвратно.** Сегодня в 18:56 UTC в логах контейнера
   `ritual_retouch` появилось сообщение
   `Telegram polling disabled because another bot instance is active` — срабатывал
   `catch` у `bot.start()` в `src/index.ts` при ошибке Telegram **409 Conflict**
   (параллельный инстанс с тем же токеном). После этого long-polling не
   перезапускался: с ~21:56 по местному времени бот не обрабатывал `/start` и любые
   другие апдейты Telegram, при этом веб-сервер продолжал работать.
   Причина конфликта — параллельный запуск второго инстанса с тем же BOT_TOKEN
   (например, локальный запуск или сторонний деплой).
2. Сам код обработчика `/start` (`src/handlers/start.ts`) корректен: сценарий
   привязки по `link_<token>` и обычный старт с `getOrCreateUser` работают,
   развёрнутый `dist` соответствовал исходникам.

## Внесённые изменения

- `src/index.ts` — вместо одноразового `void bot.start().catch(...)` с безвозвратной
  остановкой при 409 добавлен цикл перезапуска: при ошибке
  `409: Conflict` polling повторяется каждые 30 секунд; при штатной остановке
  (`bot.stop()`) цикл завершается; прочие ошибки логируются и завершают цикл.
  Благодаря этому временный конфликт инстансов больше не оставляет бота без
  обработки апдейтов навсегда.

## Выполненные проверки

1. `yarn build` (tsc) — успешно, без ошибок типов.
2. Перезапуск контейнера `docker compose restart bot` — polling восстановился
   (подтверждено: 2 установленных TCP-соединения контейнера к
   `api.telegram.org:443` через `/proc/net/tcp`).
3. Пересборка образа с новой логикой: `docker compose build bot && docker compose up -d bot`
   — образ `ritual_retouch_bot` пересобран, контейнер пересоздан и запущен.
4. Проверка деплоя: в `dist/index.js` внутри контейнера присутствует строка
   `retrying in 30s` (новая логика); ошибок `bot error|conflict|polling stopped`
   в логах нет.
5. Живой тест: пользователь отправил `/start` боту — бот ответил приветственным
   сообщением с меню. Обработка подтверждена.
6. Косвенная проверка через Telegram API: `getWebhookInfo` — webhook не установлен
   (ожидаемо, используется long-polling).

## Применение

Изменения применены: образ пересобран и контейнер перезапущен
(`docker compose build bot && docker compose up -d bot`). Бот работает в штатном
режиме.

## Рекомендации

- Не запускать параллельные инстансы бота с тем же `BOT_TOKEN` (локальный `yarn start`
  на сервере вызывает 409 Conflict у продакшн-контейнера).
